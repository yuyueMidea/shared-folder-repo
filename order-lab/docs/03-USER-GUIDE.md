# 03 · 详细使用手册

## 1. 主流程：完成一笔拼单购物

1. 启动项目，默认是“买家视角”。订单中心有12笔可直接操作的示例订单。
2. 点击“精选好物”或“创建新订单”，选择咖啡杯，点“去下单”。
3. 选规格、2人拼单、数量。示例收货地址可直接保留，也可以更改姓名、手机号和详细地址。若选择优惠券但金额不满足门槛，合计将不显示、提交被禁用；取消优惠券或增加数量即可。
4. 查看运费与应付金额，提交后进入新订单详情。此时尚未支付，倒计时30分钟。
5. 点击“模拟支付”，选择任意支付方式，再确认；不会扣钱。订单变为待成团。
6. 右侧“场景模拟器”点击“模拟好友参团”并确认，变为待发货。该按钮只是替代另一个用户，无分享链接或真实用户参与。
7. 顶部切换“商家视角”，点击“确认发货”，输入公司与单号，例如SF1234567890。
8. 场景模拟器点击“推进物流”，每次增加一条：揽收 → 运输中 → 派送中 → 已签收。第5次推进会明确提示没有更多节点。
9. 顶部切回“买家视角”，点击“确认收货”。这一步不依赖必须推进到第4条轨迹，因为实际收货可以先于模拟轨迹更新。
10. 点击“评价商品”，选择1–5星，输入至少5个字，提交。评价立即显示，重复评价按钮消失。
11. 刷新页面，订单和评价仍在；进入订单中心可检索刚创建的订单号。

## 2. 仅退款流程

买家创建单独购买订单 → 模拟支付 → 申请售后 → 选“仅退款”、填写原因 → 切商家 → 同意售后。订单关闭，支付标记已退款。未发货库存恢复，优惠券返还。

可以先做反向分支：买家在待审核时撤销，再次申请；商家拒绝并输入说明；买家详情查看拒绝原因后重新申请。历史申请保留在详情“历史售后”。

已发货订单同样可申请仅退款，但需商家同意；同意后不会把已经发出的商品加回库存。本地退款不产生真实资金流。

## 3. 退货退款流程

1. 选择待收货或已完成订单；也可直接使用示例中“待寄回”的订单。
2. 买家申请售后选择“退货退款”，填写原因。
3. 商家同意后，状态变为待寄回，此时**还没有退款**。
4. 买家“填写退货单号”，输入快递公司及8–30位单号。弹窗有虚构退货地址，只供演示，勿实际寄送。
5. 商家“收货并退款”，确认后才模拟退款成功。
6. 退款后的交易状态为已关闭；原商品、支付方式、评价和物流记录保留。

活动售后期间禁止发货、确认收货与新申请，不会一边发货一边退款。本项目仅支持审核中撤销，待寄回后不提供撤销；这是明确的教学范围。

## 4. 超时分支

进入“演示控制台”快进1小时，所有当前待付款订单超过30分钟后关闭；快进25小时，待成团订单未成团则退款关闭。该动作影响全部订单，不是仅影响最近打开的订单，因此操作前有确认框。新建订单依据当前模拟时间继续计算截止时间。

时间偏移会持久保存；刷新不会回到真实时间。若想恢复真实时间与初始订单，点击恢复初始数据。15天售后限制在提交申请时复核，超期时给出错误说明。

## 5. 筛选与统计

- 搜索支持订单号、商品名、店铺、收货人，输入即过滤，不需要按Enter。
- 店铺和时间范围与关键词组合筛选；状态标签也参与筛选。
- “待评价”=已完成且尚未提交评价；“退款/售后”包括成功、拒绝、撤销和处理中记录。
- 顶部指标是全局概览；“售后处理中”只统计待审核/待寄回/待商家收货。
- 清除筛选点击“重置”；每页5条，上一页/下一页会在边界禁用。
- 商家视角为跨店演示管理，不区分真实商家归属。

## 6. 修改模拟数据

使用VS Code或Sublime编辑 public/mockdata.json。商品价格单位为分：3990=39.90元；stock是剩余可售数。修改商品、规格、库存、券门槛及金额可以体验边界。订单商品价格和地址为快照，改产品不影响旧订单。

修改后保存文件，进入控制台“恢复初始数据”。只刷新页面通常不会载入新的种子，因为localStorage优先。不要直接把导出的绝对时间JSON当作相对时间种子；也不要随意改状态字符串。可在全新种子中设orders为空数组，只保留商品/券/地址，然后从零下单。

## 7. 故障排查

| 现象 | 检查与处理 |
|---|---|
| npm提示找不到package.json | 终端应进入解压后含package.json的order-lab目录 |
| Node版本不满足要求 | 升级至22.12+；关闭旧终端，重新打开再运行node -v |
| PowerShell禁止npm.ps1 | 使用命令提示符cmd，或执行npm.cmd install / npm.cmd run dev |
| npm网络超时 | 检查网络、代理及npm registry；这是依赖下载问题，不是mock数据问题 |
| 5173被占用 | Vite会选择可用端口，以终端显示为准；不同端口本地记录独立 |
| 双击index.html白屏 | 必须npm run dev或npm run preview，通过HTTP访问 |
| 改JSON后没变化 | 通过控制台恢复初始数据，清除旧的本地缓存 |
| 订单莫名过期 | 检查控制台是否快进过时间；恢复可重置偏移 |
| 无法付款/发货 | 核对顶部角色、订单主状态以及是否有活动售后 |
| localStorage数据损坏 | 错误页面可恢复演示数据，恢复会丢弃当前交易进度 |
| 隐私模式或配额导致无法保存 | 使用允许站点存储的正常浏览器窗口；导出已有数据后再清理 |
| 想让别人看到相同订单 | 当前无共享后端，部署后每个浏览器仍是独立数据 |

生产构建完成后只需要部署dist目录，使用静态HTTP服务；路由为Hash，不需要配置/history重写。不要将Vite开发服务直接暴露公网当生产服务。
