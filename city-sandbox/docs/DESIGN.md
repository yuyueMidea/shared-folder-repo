# v1 实施设计

## 数据与权威状态

player / car 保存位置与朝向，Three.js Mesh 只负责显示。driving 决定输入控制权和相机目标；任务由 carrying、missionIndex、money、deliveries 表示。暂停不推进时间，因此交通信号、速度和自动保存计时不会后台累积。

## 主循环

requestAnimationFrame -> 累积 dt（最多 0.1 秒）-> 最多 6 次固定 1/60 秒 tick -> 更新相机 -> 分批生成区块 -> 渲染 -> 每 8 帧更新 HUD。当前显示直接同步固定步结果，没有位置插值，后续可增加 prev/current 状态插值。

## 世界

区块为 96×96 米，地面网格道路 + 2×2 建筑地块。哈希坐标作为伪随机种子，重新访问生成相同建筑。标准档加载玩家周边 5×5 区块，流畅档 3×3；卸载范围比加载半径大一格，避免边界反复创建。每帧最多生成两个区块，初始加载在进入游戏前完成。几何体与材质共享；InstancedMesh 按区块合批并在卸载时释放实例资源，共享几何体保留到页面关闭。

碰撞根据世界公式计算，不依赖可见区块是否加载，所以没有穿过未加载建筑或掉地的网络等待问题。车辆移动拆成不超过 0.4 米的小步，圆与轴对齐建筑矩形碰撞，逐轴尝试移动实现滑墙。道路为平面，不模拟重力。

## 交通

20 个交通对象复用，各自在水平或垂直有向车道上直行。通过车道前向距离检查前车与玩家，再结合路口距离和 16 秒信号周期得到目标速度。加减速限幅，不直接瞬间跳速。远离玩家的车辆重定位至外围。简单版本不保证所有交通冲突可解；R 提供玩家恢复途径。

## 交互和存档

上车需要距离 <4.5 米。下车速度 <1.5 m/s，测试车身两侧的位置是否被建筑和交通占用。交付必须步行且距目标 <4 米，领取和完成分别修改 carrying 状态，避免重复领取同一个奖励。存档带 version:1；NaN、无限值、不合理坐标和非整数配送数量拒绝恢复。存储异常降级为本次游玩。

## 扩展路线

1. 把 main.js 拆为 Input、Player、Vehicle、Traffic、Camera、Mission、Save 系统，维持纯函数测试层。
2. 用 Rapier 替换碰撞与车辆：胶囊角色、raycast vehicle、刚体交通；以物理刚体作为位置权威。
3. 添加显式车道图、转弯连接、路口预约与死锁恢复。
4. 增加行人路径、音效、可配置任务、GLB 资产与资源加载队列。
5. 加入模拟插值、相机形状扫描、移动方向预加载、浮动原点和存档迁移。

当前依赖 Three.js 0.180.0 / Vite 6.1.0，均固定版本，便于复现。原型以桌面浏览器和键鼠为目标。
